Architecture

The codebase has a strict layering rule: the async wrapper holds no storage logic. Every write goes through WAL → MemTable → flush → SegmentStore in that order.

3-Phase Flush Protocol

Flush converts the current memtable into an immutable on-disk segment without blocking writes during I/O. The engine stays writable throughout Phases 1 and 2.

Engine::begin_flush() write lock

Snapshot memtable entries into a FlushWork. Reserve the next segment ID. The memtable is not cleared — writes continue while the snapshot is on disk.

// records max LSN across all snapshot entries let flushed_max_lsn = entries.iter().map(|(_, e)| e.lsn).max().unwrap_or(0);
FlushWork::execute() no lock held

Writes all four segment files to disk. No engine state required. In AsyncEngine, this phase runs in spawn_blocking.

// all disk I/O happens here — engine is unlocked segment-NNNNNNNN.dat // LZ4 compressed data blocks segment-NNNNNNNN.idx // sparse key index segment-NNNNNNNN.xf // Xor8 probabilistic filter segment-NNNNNNNN.meta // JSON metadata
Engine::finalize_flush(&meta, flushed_max_lsn) write lock

Register the segment in the manifest. Open a SegmentReader. Rebuild the memtable, keeping only entries whose lsn > flushed_max_lsn.

// entries written during Phase 2 survive the flush let rebuilt: Vec<_> = self.memtable.iter() .filter(|(_, e)| e.lsn > flushed_max_lsn) .collect();
Invariant: Entries at lsn ≤ flushed_max_lsn are durably in the segment after Phase 3. Entries at lsn > flushed_max_lsn arrived during Phase 2 and are retained.
Covered by test: test_finalize_flush_retains_writes_after_snapshot

Segment File Format

Four files per segment. ID is zero-padded 8-digit decimal: segment-00000001.dat.

.dat

Data blocks

4096-byte aligned, LZ4-compressed. Magic: 0x45445347 (EDSG)

.idx

Sparse index

First key of every 64th entry + byte offset in .dat

.xf

Xor8 filter

Probabilistic filter — eliminates unnecessary .dat reads. No false negatives.

.meta

Metadata

JSON — segment_id, record_count, min/max_key, BLAKE3 hash, cohort

MemTable Implementations

Three implementations in memtable.rs. Default is BBTreeConcurrentMemTable, set in EdgestoreConfig::default().

TypeBackendConcurrencyNotes
BTreeMemTable std::collections::BTreeMap &mut self writes Reference implementation
BBTreeMemTable bbtree::unsync::BBTreeMap &mut self writes ~5× faster point lookups via SIMD node search
BBTreeConcurrentMemTable bbtree::BBTreeMap concurrent reads Default. Readers never write cache lines during read. Uses scan() not range(). Manual count field (no .len()). OOM panics.

impl_simple_memtable! macro memtable.rs:58

BTreeMemTable and BBTreeMemTable share identical MemTable impl bodies — both backing types expose the same interface. The macro generates the impl from a single body to prevent silent divergence. BBTreeConcurrentMemTable is not covered: it uses scan() instead of range()/iter() and has different allocation semantics.

macro_rules! impl_simple_memtable { ($name:ident) => { impl MemTable for $name { fn insert(&mut self, key: Vec<u8>, entry: MemEntry) { self.inner.insert(key, entry); } fn get(&self, key: &[u8]) -> Option<MemEntry> { self.inner.get(key).cloned() } // range(), prefix(), iter(), len(), clear() follow the same pattern } }; } impl_simple_memtable!(BTreeMemTable); impl_simple_memtable!(BBTreeMemTable);
OOM behavior: BBTreeConcurrentMemTable::insert panics on allocator exhaustion. This is documented on the MemTable::insert trait and on the impl. The other two implementations do not panic.

Tiger Style Rules in Force

This codebase applies Tiger Style constraints. The rules below are actively enforced — each one has at least one code site where it was applied or repaired.

Assertions

Minimum 2 debug_assert! per non-trivial function: entry condition + return-value invariant. Assert at every external call boundary.

debug_assert!(!ns.is_empty(), "ns must not be empty"); // ... body ... debug_assert!(lsn > 0, "lsn must be positive");
No Silent Error Discard

Every Result is handled explicitly. let _ = expr is banned on fallible paths that affect correctness.

// before (silent discard): let _ = self.flush_to_segments_inner(); // after (error propagates): self.flush_to_segments_inner()?;
Loop Bounds

Every non-trivial loop has an explicit upper bound with an assertion.

let blocks_max = (dat_len / SEGMENT_BLOCK_SIZE as u64) + 1; let mut blocks_visited = 0u64; loop { debug_assert!(blocks_visited <= blocks_max, "exceeded block bound"); blocks_visited += 1; }
Function Size & Purpose

Max 70 lines per function. One purpose per function — must be nameable as a verb-noun pair. merge_sorted_scans only merges. dedup_filter_scan only deduplicates. write_entry only writes one WAL record.
