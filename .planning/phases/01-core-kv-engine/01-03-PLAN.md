<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller→insert | Caller-supplied encoded key and MemEntry values cross into memtable storage |
| engine→range/prefix | Engine-supplied range bounds determine what data is returned — incorrect bounds could return cross-namespace data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | prefix() cross-namespace bleed | mitigate | Prefix scan uses namespace-encoded prefix as discriminant; namespace "a" prefix cannot match namespace "ab" prefix due to length-prefixed encoding; unit test confirms isolation |
| T-03-02 | Tampering | insert key overwrite | accept | Last insert wins at memtable level; engine layer enforces single-writer so concurrent overwrites cannot occur; WAL LSN ordering ensures deterministic recovery |
| T-03-03 | Denial of Service | unbounded memtable growth | accept | Memtable flush threshold is engine concern (Phase 2); MemTable trait has no size enforcement; document that callers must flush when len() exceeds threshold |
| T-03-04 | Tampering | memtable_factory Box<dyn Fn> | accept | Factory is set at DB open time by trusted caller code; no user-controlled injection path |
</threat_model>
