<objective>
Create the foundational vector types and encoding layer. This is the type system that all later vector plans build on.

1. `Dtype` enum: f32=0, f16=1, i8=2. Each maps to a specific byte width per element.
2. `VectorRecord` struct: dims (u16), dtype (Dtype), data (Vec<u8>).
3. Encoding: 3-byte header (dims as big-endian u16, dtype as u8) followed by raw element bytes.
4. Decoding: reverse of encoding, with validation.
5. Validation: `dims * element_width == data.len()` must hold on encode.
6. No new external crates for this plan (half crate for f16 is Plan 05-03).

Output: edgestore/src/vector/types.rs, edgestore/src/vector/mod.rs, updated edgestore/src/lib.rs
</objective>

    - `VectorRecord` struct:
      ```rust

      pub struct VectorRecord {
          pub dims: u16,
          pub dtype: Dtype,
          pub data: Vec<u8>,
      }
      ```
    - `pub fn encode_vector_record(record: &VectorRecord) -> Result<Vec<u8>, EdgestoreError>`:
      - Validates `record.data.len() == record.dims as usize * record.dtype.element_size()`
      - On mismatch: `EdgestoreError::DimensionMismatch { expected, actual }`
      - Output: [dims_hi, dims_lo, dtype_byte, ...data...]
      - Uses big-endian for dims (consistent with existing project byteorder conventions)
    - `pub fn decode_vector_record(bytes: &[u8]) -> Result<VectorRecord, EdgestoreError>`:
      - Minimum 3 bytes; else `EdgestoreError::CorruptData("vector record too short")`
      - Reads dims (big-endian u16), dtype (u8 → Dtype::try_from), data (remaining bytes)
      - Validates data length matches dims * element_size
    - No serde derives on VectorRecord (raw bytes are opaque; serde not needed)
  </behavior>
