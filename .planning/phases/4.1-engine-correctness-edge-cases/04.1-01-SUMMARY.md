## What was done

Added inline WAL rotation to `Engine` so long-running sessions rotate the WAL at the
`wal_max_bytes` (or `wal_max_age_secs`) boundary without requiring a close/reopen cycle.

Changes made:

1. **`edgestore/src/engine.rs`** — Added private method `rotate_wal_if_needed(&mut self) -> Result<(), EdgestoreError>` placed between `delete` and `range`. The method computes `now_secs`, checks `self.wal.needs_rotation(now_secs)`, and if rotation is needed fsyncs the current WAL file then creates a new one via `WalWriter::create` using `next_wal_path`.

2. **`Engine::put`** — Added `self.rotate_wal_if_needed()?;` immediately after `self.wal.append(&record)?;`.

3. **`Engine::put_with_ttl`** — Added `self.rotate_wal_if_needed()?;` immediately after `self.wal.append(&record)?;`.

4. **`Engine::delete`** — Added `self.rotate_wal_if_needed()?;` immediately after `self.wal.append(&record)?;`.

5. **`Engine::commit_transaction`** — Added `self.rotate_wal_if_needed()?;` after the group-commit `self.wal.fsync()?;`.

## Tests

- **`test_wal_rotates_inline_without_reopen`** added to `edgestore/tests/integration_core.rs`.
  Opens an engine with `wal_max_bytes = 300`, writes 10 puts, flushes, then asserts that
  `count_wal_files >= 2` (rotation happened inline). Drops the engine, reopens with default
  config, and verifies all 10 keys are recoverable.

- All 99 existing unit tests + 12 integration_core + 10 integration_segments tests continue to pass.
- `cargo build --workspace` exits 0.
- `cargo test --workspace -- test_wal_rotates_inline_without_reopen` exits 0.
