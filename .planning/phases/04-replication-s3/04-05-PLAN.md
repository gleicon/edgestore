<objective>
Write integration tests for all 5 Phase 4 success criteria.

Tests split into two files by dependency:
- `edgestore/tests/integration_replication.rs` — SC2, SC3, SC4: no HTTP server needed; exercises Engine API and FilesystemRemoteStore directly. Always runs in CI.
- `edgestore-repl/tests/integration_replication.rs` — SC1, SC5: requires starting a real tiny_http server. Always runs (127.0.0.1 loopback, no external services needed).

Success criteria from the decisions and protocol redesign:
- SC1: Two-engine sync via HTTP. Engine A writes and flushes. AntiEntropyLoop on B detects Merkle diff, pulls segment, B reads all records. This is the primary end-to-end test of the pull-only protocol (D02, D08).
- SC2: Cursor durability. Simulate interrupted download. Retry picks up from cursor (Applied segments are Skipped on re-import). This tests the D08 durable-progress guarantee.
- SC3: LWW conflict resolution (D06). Same key on both nodes with different timestamps. Higher timestamp wins. On collision, lower HostId wins.
- SC4: FilesystemRemoteStore round-trip. Upload segment bytes, download them back, verify BLAKE3 matches the original hash. This is the unit acceptance test for D05.
- SC5: ?debug=json endpoint (D07). GET /merkle?debug=json and GET /segments?debug=json return valid JSON with correct field names.

Purpose: Gate Phase 4 completion. All 5 tests must pass before moving to Phase 5.

Output: edgestore/tests/integration_replication.rs, edgestore-repl/tests/integration_replication.rs
