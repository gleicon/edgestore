## Objective

Document and pin the TTL lazy-expiry contract: `Engine::get`, `Engine::range`, and `Engine::prefix` return expired records (past TTL) until compaction removes them. This is intentional behavior — lazy expiry avoids per-read TTL checks and keeps the hot path simple. The contract must be explicit in doc comments and locked in by an integration test.

## Context

`Engine::get` (engine.rs ~line 209) reads from memtable then segment store. Neither path checks `entry.ttl` or `entry.timestamp` against wall clock. A record inserted with `put_with_ttl(key, val, 1)` continues to be returned by `get` after 1 second expires — until `compact_once()` runs and the cohort is collected.

This is the correct design (see prod.md: deathtime-cohort compaction, lazy GC). The bug is purely the absence of documentation and a regression test. No code change to the read path is needed.

<action>
Append a new test `test_ttl_lazy_expiry_visible_before_compaction` to `edgestore/tests/integration_core.rs`.

Test body:
1. `open_engine(&dir)` → mutable `engine`
2. `engine.put_with_ttl(b"ns", b"expiring", b"still_here", 1).unwrap()` — TTL = 1 second
3. `std::thread::sleep(std::time::Duration::from_secs(2))` — wait for TTL to expire
4. `let val = engine.get(b"ns", b"expiring").unwrap();`
5. `assert_eq!(val, Some(b"still_here".to_vec()), "lazy expiry: value must be visible before compaction even after TTL expires");`
6. `engine.compact_once().unwrap();`
7. `let val_after = engine.get(b"ns", b"expiring").unwrap();`
8. `assert_eq!(val_after, None, "value must be gone after compaction removes expired cohort");`

Note: step 8 relies on the 1-hour cohort window being skipped by the compaction because the ttl on the record sets death_time in the past. The compact_cycle uses `now_nanos` which is already past the record's death_time after sleeping 2 seconds.
</action>

- Test calls `compact_once` then asserts `get` returns `None`
- `cargo test --workspace -- test_ttl_lazy_expiry_visible_before_compaction` exits 0
</acceptance_criteria>
