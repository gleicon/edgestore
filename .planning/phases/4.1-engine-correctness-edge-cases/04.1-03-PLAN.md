## Objective

Fix `SegmentReader::range_scan` to use exclusive-end semantics (`[start, end)`) matching `BTreeMemTable::range` and the documented `Engine::range` API contract. Currently line 455 of `segment.rs` uses `k > end` (inclusive end); it must be `k >= end` (exclusive end). Update all callers and tests affected by this change.

## Context

`BTreeMemTable::range` (memtable.rs line 43) already uses `Bound::Excluded(end.to_vec())` — exclusive end. `Engine::range` passes `enc_end` directly to both `segment_store.range_scan` and `memtable.range`. After this fix both paths will use the same exclusive-end semantics.

`prefix_upper_bound` computes an end key that is strictly after all keys with the given prefix (by incrementing the last non-0xFF byte), so prefix scans are unaffected by this change.

Two existing tests assert inclusive-end counts and must be updated:
1. `segment.rs::test_reader_range_scan_100_entries` — end key `key-0199` must become `key-0200` to keep 100 results
2. `snapshot.rs::test_snapshot_range_returns_sorted_pairs` — end key `key-0006` must become `key-0007` to keep 5 results; update the adjacent comment

`Snapshot::range` passes `enc_end` to `reader.range_scan` — benefits from the fix automatically.
