<objective>
Create the `edgestore-tokio` crate — an async wrapper around the sync `edgestore` core. Per architecture constraint: no async in the core crate; async belongs in the separate crate.

1. Add `edgestore-tokio` as a workspace member in Cargo.toml
2. Create `edgestore-tokio/Cargo.toml` with `tokio` and `edgestore` dependencies
3. `AsyncEngine` struct wraps `Engine` in `tokio::sync::RwLock`
4. Async methods mirror Engine methods: open, get, put, delete, prefix_scan, vector_put, vector_get, vector_delete, vector_search, build_vector_index
5. Heavy ops (vector_search, build_vector_index, prefix_scan on large data) use `tokio::task::spawn_blocking`
6. Lightweight ops (get, put, delete) return immediately (Engine is Send so can be moved into blocking task)
7. `open_async(path, config)` → `AsyncEngine::new(path, config)` using `spawn_blocking(|| Engine::open(path, config))`

Output: edgestore-tokio/src/lib.rs, edgestore-tokio/Cargo.toml, updated Cargo.toml
</objective>

      ```rust
      }
      ```
    - `AsyncEngine::open(path, config) -> Result<Self, EdgestoreError>`:
      - Uses `spawn_blocking(|| Engine::open(path, config))` then wraps in Arc<RwLock>
    - Read operations (get, prefix_scan, vector_get, vector_search, etc.):
      - Acquire `read().await` lock
      - For heavy ops (vector_search, build_vector_index): clone Engine (it's Send), move into `spawn_blocking`, return result
      - For lightweight ops (get, put, delete): can run directly under the lock
    - Write operations (put, delete, vector_put, vector_delete):
      - Acquire `write().await` lock
      - `put` and `delete` are lightweight — run directly
    - All methods return `Result<T, EdgestoreError>` wrapped in `Result<T, EdgestoreError>` (no nested Results)
    - Re-export `EdgestoreConfig`, `EdgestoreError`, `MetricsSnapshot` from edgestore for convenience
  </behavior>
