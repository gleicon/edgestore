<objective>
Create three new pure-Rust modules in the edgestore crate:

1. `merkle.rs` — Range-level Merkle tree over 16 key-range buckets. Its role in Phase 4 is strictly as an anti-entropy probe: two nodes compare roots first; if roots match, sync is skipped entirely; if roots differ, the sync path proceeds to a manifest-diff (Plan 04-02). The Merkle tree does NOT route which key ranges to sync — that is manifest-diff's job (D02).

2. `replication.rs` — Simplified, pull-only replication protocol: types (HostId, SegmentRef) and the `ReplicationProtocol` trait. The trait has exactly 3 methods matching the pull-only model: `merkle_root` (probe), `list_segments` (manifest), `fetch_segment` (transfer). No push, no delta routing, no LSN ack in this trait.

3. `remote_store.rs` — The `RemoteStore` trait defining the interface for durable segment backends. Phase 4 implements `FilesystemRemoteStore` only (Plan 04-04). S3 is a future phase (D04, D05).

All modules compile clean with existing deps (blake3 already in Cargo.toml). No new external deps for this plan.

Purpose: Establish the type contracts that Plans 04-02 through 04-05 build against. Executors for later plans receive these types as explicit context rather than discovering them from the codebase.

Output: edgestore/src/merkle.rs, edgestore/src/replication.rs, edgestore/src/remote_store.rs, updated edgestore/src/lib.rs
</objective>

    - `RangeMerkleTree::differing_buckets(&self, other: &RangeMerkleTree) -> Vec<u8>`:
      - Return bucket indices (0-15) where self.buckets[i] != other.buckets[i]
    - `RangeMerkleTree::empty() -> Self` — all-zero buckets
    - No serde derives on RangeMerkleTree itself (arrays are not serde-friendly by default; only the root [u8;32] is serialized over the wire, not the full tree)
    - Unit tests in the same file:
      - `test_empty_tree_roots_equal`: two empty trees have equal roots
      - `test_build_single_segment`: one segment → bucket hash matches BLAKE3 of that segment's merkle_root
      - `test_differing_buckets`: two trees differ in bucket 3 → differing_buckets returns [3]
  </behavior>
