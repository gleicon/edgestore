## Objective

Add a multi-segment divergence regression test proving that `Snapshot::get` returns the highest-LSN value when the same key exists in multiple pinned segments, regardless of segment ID ordering. The LWW logic was implemented in Phase 3 (`is_none_or(|b| entry.lsn > b.lsn)` in snapshot.rs line 127), but no test covers the case where segments disagree on a key's value.

## Context

`Snapshot::get` (snapshot.rs line 120) iterates `self.segment_ids` in order and tracks `best: Option<MemEntry>`. For each segment containing the key, it checks `entry.lsn > b.lsn` and replaces `best` if the new entry has a higher LSN. This is correct regardless of segment ID ordering — the highest-LSN entry wins.

The existing test `test_snapshot_get_reads_pinned_segment` only writes one segment. The divergence test requires two segments containing the same key with different LSNs, and must verify that ordering the segment IDs in both `[low_id, high_id]` and `[high_id, low_id]` returns the same (highest-LSN) value.

5. Case A — segment IDs in ascending order [0, 1]:

   - `drop(snap);`
6. Case B — segment IDs in descending order [1, 0]:
   - `let reg2 = SnapshotRegistry::new(); let snap_id2 = reg2.register(&[1, 0]);`
   - `let snap2 = Snapshot::new(snap_id2, reg2.clone(), vec![1, 0], dir.path().to_path_buf());`
   - `assert_eq!(snap2.get(b"ns", b"shared_key").unwrap(), Some(b"new_value".to_vec()), "descending order: highest LSN must still win");`
