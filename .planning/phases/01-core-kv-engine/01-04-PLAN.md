<objective>
Build the KV engine that wires WAL, memtable, and key encoding into the public API. The single-writer invariant is enforced here via a filesystem lockfile. Group commit accumulates WAL appends and issues a single fsync per flush cycle.

Purpose: This is the first plan that produces something a caller can use end-to-end: open a database, write a key, read it back. All Phase 1 API surface (put, get, delete, range, prefix, put_with_ttl) is delivered here.

Output: `edgestore/src/engine.rs` with all KV API methods plus single-writer enforcement and group commit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller→Engine KV API | Caller-supplied namespace, key, value bytes cross into WAL and memtable |
| filesystem→lockfile | OS filesystem lock mechanism enforces single-writer invariant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Single-writer lockfile | mitigate | Use `fs2::FileExt::try_lock_exclusive` for OS-enforced exclusive lock; not a user-space mutex (cannot be bypassed by a second thread calling Engine::open) |
| T-04-02 | Denial of Service | Unbounded key/value sizes | mitigate | Validate ns.len() <= u16::MAX via encode_key (returns NamespaceTooLong error); add key size check: return InvalidOperation if key.len() > 65536 or val.len() > 64 * 1024 * 1024 (64 MB) |
| T-04-03 | Tampering | Namespace isolation via prefix encoding | mitigate | Key encoding uses length-prefixed ns so namespace "a" prefix never matches namespace "ab" keys; range bounds enforced by encode_key producing correct sort-order boundaries |
| T-04-04 | Repudiation | WAL lsn_counter monotonicity | mitigate | lsn_counter incremented before WAL append and never decremented; recovery (plan 01-06) will restore lsn from max WAL LSN on open |
| T-04-05 | Information Disclosure | value bytes in memtable | accept | At-rest encryption is out of scope v1; data accessible to any process with read access to the DB path |
| T-04-SC | Tampering | fs2 crate install | mitigate | Verify fs2 on crates.io before cargo add; check download counts and owner identity |
</threat_model>
