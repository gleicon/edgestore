<objective>
Create the `edgestore-repl` workspace crate providing the HTTP transport layer and pull-only anti-entropy loop.

Wire format (D07): All control messages use MessagePack via `rmp-serde`. Raw bytes for segment data transfer. All endpoints support `?debug=json` for human inspection.

HTTP endpoints (3, matching the simplified ReplicationProtocol trait from Plan 04-01):
- `GET /merkle` → `{root: [u8; 32]}` in MessagePack — anti-entropy probe value
- `GET /segments` → `[{segment_id: u64, segment_hash: [u8; 32]}]` in MessagePack — full manifest
- `GET /segments/{hash_hex}` → raw segment bytes, Content-Type: application/octet-stream

No push endpoint. No LSN ack endpoint. No delta-by-range endpoint. Pull-only (D08).

AntiEntropyLoop (D08): background thread that wakes every N seconds, probes a peer's Merkle root, and if different pulls all missing segments one by one. Per-peer cursor file makes progress durable across crashes.

The server wraps `Arc<Mutex<Engine>>` — engine access is serialized, correct for single-writer constraint.

Purpose: Deliver the network layer and sync loop. Plans 04-04 and 04-05 build on top of these.

Output: edgestore-repl crate with http_client.rs, http_server.rs, anti_entropy.rs
</objective>

      - `#[derive(serde::Serialize, serde::Deserialize, Default)]`
        `pub struct PeerCursor`:
        - `last_known_merkle_root: Vec<u8>` — 32 bytes stored as Vec for serde compat
        - `segments_pending: Vec<Vec<u8>>` — each is a 32-byte hash as Vec
        - `last_attempt_secs: u64`
        - `segments_applied_total: u64`
      - `pub struct AntiEntropyLoop`:
        - `engine: Arc<Mutex<edgestore::Engine>>`
        - `peer_url: String`
        - `peer_id: String`
        - `db_path: PathBuf`
        - `interval_secs: u64` — default 30
      - `pub fn new(engine: Arc<Mutex<edgestore::Engine>>, peer_url: String, peer_id: String, db_path: PathBuf) -> Self`
      - `pub fn start(self) -> std::thread::JoinHandle<()>`:
        - Spawns std::thread::spawn; loop body:
          1. Sleep interval_secs (std::thread::sleep)
          2. Load or create cursor from `{db_path}/sync/{peer_id}.cursor` (MessagePack via rmp-serde)
          3. Update `cursor.last_attempt_secs = now_secs()`
          4. Create `HttpReplicationClient::new(&peer_url)`
          5. `let peer_root = client.merkle_root()` — on error, log and continue loop
          6. Lock engine, call `engine.compare_merkle(&peer_root_bytes)` — if true (in sync), update cursor root and flush, continue loop
          7. `let peer_segments = client.list_segments()` — on error, log and continue
          8. Lock engine (release previous lock first), call `engine.missing_segments(&peer_segments)` → Vec<[u8;32]>
          9. Set `cursor.segments_pending = missing.iter().map(|h| h.to_vec()).collect()`; flush cursor
          10. For each hash in segments_pending (in order):
              - `let data = client.fetch_segment(&hash)` — on error, log and continue to next
              - Lock engine, call `engine.import_segment(&data, &hash)`
              - On ImportResult::Applied or Skipped: remove hash from cursor.segments_pending, increment segments_applied_total, flush cursor
              - On ImportResult::HashMismatch: log warning, skip (do not remove from pending — will retry)
          11. Update `cursor.last_known_merkle_root` to peer_root_bytes; flush cursor
      - Cursor file path: `{db_path}/sync/{peer_id}.cursor`
      - Create `{db_path}/sync/` directory if it does not exist before first cursor write
      - Cursor flush: serialize with `rmp_serde::to_vec(&cursor)`, write to `{cursor_path}.tmp`, rename to final (atomic)
      - `fn now_secs() -> u64`: `std::time::SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or_default().as_secs()`
